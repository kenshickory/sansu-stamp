MAKING OF ／ 2026.08

算数アプリができるまで

小学1年生むけの算数アプリを、AIエージェント（Claude Code）との対話だけで作った記録です。実際に送った文章と、AIが返してきた質問をそのまま載せています。コードは1行も手で書いていません。

🐰 できたアプリを開く ⏱ 対話10往復ほど
01 ／ 全体像

「作らせる」んじゃなくて「決めていく」

いちばん大事なのは、最初のプロンプトの上手さではありません。AIに質問させて、こちらが選ぶという形にすることです。

ざっくり頼むと、AIは足りない情報を勝手に埋めて、それっぽい完成品を一発で出してきます。動くには動くけれど、たいてい「思ってたのと違う」ものが出てくる。そこから直そうとすると、AIは全体を書き直そうとして、直すたびに別のところが壊れます。

先に質問させて、選択肢から選んでおけば、この作り直しがまるごと消えます。

02 ／ 最初のプロンプト

実際に送った文章はこれだけ

あなた
友人の娘さんが小学校低学年なんだけど、算数の問題のウェブアプリを作って渡してあげようと思っています。 習慣化させる機能もついていて、算数をしっかり勉強できるようにするには、どのような機能にしたらいいと思う？ しっかり作りたいから、必要なことは必要なだけ聞いて。

技術の話はゼロです。「React で」とか「localStorage に保存して」とか、一切書いていません。書く必要がありません。

この短い文章の中に、効いている要素が4つ入っています。

友人の娘さんが小学校低学年1なんだけど、算数の問題のウェブアプリ2を作って渡してあげようと思っています。習慣化させる機能もついていて、算数をしっかり勉強できるように3するには、どのような機能にしたらいいと思う？ しっかり作りたいから、必要なことは必要なだけ聞いて4。
1　だれが使うか 「小学校低学年の女の子」。これがあるだけで、文字はひらがな、ボタンは大きく、キーボードは使わせない、と全部が決まります。
2　なにを作るか 「ウェブアプリ」。渡し方（URL）と、動く場所（ブラウザ）がここで決まります。
3　どうなってほしいか 「習慣化」「しっかり勉強できる」。機能ではなく目的を書く。機能はAIが提案します。
4　聞いていい、という許可 これが無いとAIは推測で進みます。この一言で、AIは勝手に決めるのをやめて確認しに来ます。
POINT

4つの中でいちばん効くのは 4「必要なことは必要なだけ聞いて」です。これが無いと、他の3つがどれだけ丁寧でも、AIは残りを推測で埋めます。

03 ／ AIからの質問

選択肢つきで聞いてくる。タップするだけ

まずAIは「自分ならこう作る」という案を先に出し、そのうえで答えによって作りが変わるところだけを4つ聞いてきました。

AI
芯になる3つ（ここが効く） 1. 1回5分・10問のセット制 —「今日のぶん おわり！」で必ず終わる 2. まちがい直しの自動復習 — 間違えた問題を翌日・3日後・7日後に自動で再出題 3. 正答率で難易度が自動で上下 …（低学年向けUX・保護者向け機能の案が続く）… 作る前に4つだけ確認させて。ここで作りが変わる。
Q1 ／ 学年
いま学校でやってるあたりは？

小1／小2／小3／学年をまたいで選べる形　の4択

Q2 ／ 端末
何で使う？

iPad／スマホ／PC（複数選択可）

Q3 ／ 配布
どうやって渡す？

URL共有／HTMLファイル／まだ決めてない

Q4 ／ 保護者機能
おうちの人向けはどこまで？

レポート＋設定／設定だけ／要らない

選んだ答えは「学年をまたいで選べる形」「iPad とスマホ」「URL共有」「レポート＋設定」。ここまでで、こちらが書いた文字は最初の3行だけです。

このあとAIは設計案を出し、さらに3つ質問してきました（1日の問題数／ごほうびの世界観／このまま実装していいか）。「10問×1セット」「おまかせ」「このまま全部作って」と答えて、実装に入りました。

なぜ質問が効くのか

AIが聞いてきた4つは、どれも「答えが変わると作り直しになる」ところです。端末がPCだと決まればキーボード入力を許す設計になり、iPadだと決まれば画面内テンキーになる。これを後から変えるのは、最初に決めるより10倍高くつきます。

04 ／ 設計の合意

作る前に、文章で全部見せてもらう

質問に答えたあと、AIはコードを書く前に設計を日本語で出してきました。ここが違和感を消す最後のタイミングです。ここで「やっぱりタイマーは付けたい」と言えばタダですが、完成後に言うと作り直しになります。

01
こども画面 ホームは「きょうのミッション」1つだけ。1セット10問、画面内テンキー、ふりがな付きひらがな。不正解は「おしい！もういちど」で×を出さない。
02
単元（小1メイン＋小2も解放できる） 10のあわせかた／たしざん／ひきざん／3つのかず／くりあがり／くりさがり／ぶんしょうだい。小2（100までのかず・2けた・九九・とけい）は初期OFF。
03
習慣化のしくみ スタンプカレンダー、れんぞく日数、おやすみけん（週2枚）、コイン＆コレクション24種。
04
おうちの人ページ 4桁の暗証番号で開く。週次レポート（やった日数・問題数・正答率・苦手単元）と設定。
AIが自分から言ってきた注意点

「URL共有＋端末内保存なので、iPad とスマホで進捗は別々になります。同期は仕組み的に不安定なのでおすすめしません。代わりにデータの書き出し／読み込みを付けます」——都合の悪いことを先に言わせるのも、質問させる形にした効果です。

05 ／ 実装と検証

AIに、自分で作ったものをテストさせる

ここがいちばん大事な工程です。AIは「できました」と言いますが、その言葉には根拠がありません。実際に動かして確かめさせるところまでを1セットにします。

今回は、AIが自分でブラウザを開き、問題を作る部分を 11単元 × 3レベル × 400回 ＝ 13,200問 自動生成して、問題文と答えが一致するかを全件チェックしました。人間には無理な量ですが、AIには数十秒です。

そのまま使える一言

実装を頼むときに 「作ったら、自分で動かして確かめてから報告して」 と付けるだけで、品質がはっきり変わります。「テストも書いて」でも同じ効果があります。

06 ／ できたもの

学力が伸びるのは「まちがい直し」の部分

見た目はスタンプとシールですが、実際に効いているのは間隔をあけた再出題です。まちがえた問題は消えずに、忘れかけたタイミングで戻ってきます。

07 ／ 型

コピーして使えるプロンプト

オレンジの部分を自分の内容に入れ替えるだけです。長く書く必要はありません。

TEMPLATE ／ 何かを作ってもらうとき
〔だれ〕が使う 〔なに〕を作りたい。

〔どうなってほしいか。機能ではなく目的を書く〕ようにするには、
どんな作りにしたらいいと思う？

しっかり作りたいから、必要なことは必要なだけ聞いて。
TEMPLATE ／ 実装をお願いするとき
この内容で作って。

作り終わったら自分で動かして確かめて、
確かめた結果だけを報告して。
動かしていないことは「動いた」と言わないで。
TEMPLATE ／ 直してほしいとき
〔どこが〕が 〔どうなっている〕。
本当は 〔こうなってほしい〕。

他のところは触らないで、そこだけ直して。
最後の1行が効く

「他のところは触らないで」を付けないと、AIは親切心で周りも書き換えて、動いていた部分を壊すことがあります。修正のたびに付けてください。

08 ／ 引き継ぎ

このアプリを、自分で改造していく

このアプリは HTMLファイル1個で全部できています。サーバーもデータベースもGitHubも要りません。ファイルを1つ受け取って、そのフォルダでAIを開けば、その日から改造できます。

01
ファイルを置く 受け取った index.html を、好きなフォルダに入れます。たとえば ~/sansu/index.html。中身はこの1ファイルだけで、他に必要なものはありません。
02
そのフォルダでAIを開く Claude Code をそのフォルダで起動します。ターミナルなら cd ~/sansu してから claude。これで、AIがそのファイルを直接読み書きできる状態になります。
03
日本語で頼む 「index.html が算数アプリです。九九を最初からONにして、あと『たしざんめいじん』みたいな称号を追加して」——この調子で大丈夫です。コードを読む必要はありません。
04
自分で公開する 「これを公開してURLにして」と頼めば、自分のアカウントのURLが発行されます。そこから先は自分のアプリです。更新しても同じURLのままで、お子さんの進捗も消えません。
先に知っておくこと

AIに任せて改造していくと、今まで動いていた部分が壊れることがあります。「ボタンの色を変えて」と頼んだのに、なぜか採点がおかしくなる。これは珍しいことではなく、普通に起きます。
だから、直す前に「戻れる場所」を作っておきます。

09 ／ 保険

Gitで「戻れる場所」を作っておく

Gitはプログラマー向けの難しい道具に見えますが、ここで使うのは「その時点の状態を保存する」という一点だけです。ゲームのセーブと同じで、覚えるコマンドは3つで足ります。

GitHub（インターネット上にコードを置くサービス）は使いません。自分のパソコンの中だけで完結します。

1／最初の1回だけ
cd ~/sansu
git init
git add .
git commit -m "もらった最初の版"
2／直して、動いたら（毎回）
git add .
git commit -m "九九を最初からONにした"
3／壊れたとき
git checkout -- .

3番は「最後にコミットした状態に戻す」という意味です。ここまでの変更は消えますが、コミット済みのところまでは必ず戻ります。これがあるだけで、思い切って試せるようになります。

じつは、コマンドを覚えなくてもいい

Claude Code はGitも操作できます。動作を確認したあとに 「いまの状態でコミットして」 と言えば、そのまま保存してくれます。壊れたときも 「さっきのコミットまで戻して」 で戻せます。
最初の git init だけ1回打っておけば、あとは日本語で足ります。

コミットするタイミング

TIMING 01
ひとつ直して、動いたとき

いちばん大事。「動く状態」を1つずつ積み上げていきます。1機能＝1コミットが目安です。

TIMING 02
大きい変更を頼む前

「デザインを全部やり直して」の直前。気に入らなければ丸ごと捨てられます。

TIMING 03
その日の作業を終えるとき

中途半端でも構いません。翌日「昨日どこまでやったか」が残ります。

GitHubは、こうなったら考える

—
1台のパソコンで、自分だけで直す GitHubは要りません。ここまでのやり方だけで足ります。
＋
会社のPCと自宅のPC、両方で作業したい GitHubに置けば、どちらからでも取り出せます。
＋
誰かと一緒に直したい 同じ場所を見ながら、それぞれが直せるようになります。
＋
パソコンが壊れても残したい バックアップとして。GitHubでなくクラウドドライブへのコピーでも構いません。
10 ／ 応用

同じやり方が、仕事でもそのまま効く

CASE 01
娘さん用の問題集をもう1本

「漢字の書き取り」「英単語」も、単元とレベルを差し替えるだけで同じ構造で作れます。今回のアプリを見せて「これの漢字版を」と言えば通ります。

CASE 02
くり返しやっている手作業

毎週の集計、ファイル名の整理、CSVの変換。「毎週こういう作業をしている、自動化したい、必要なことは聞いて」から始めます。

CASE 03
社内で共有する資料や表

この記録のページ自体もAIが作っています。「◯◯を、図も入れて分かりやすくHTMLでまとめて」で出てきます。

11 ／ 注意

これをやると、たいてい失敗する

01
1回のメッセージに要望を詰め込む 「あれもこれも」と10個並べると、AIは半分しか実装しません。1メッセージ1テーマにして、終わったら次へ。
02
技術用語を無理に使う 知らない言葉を混ぜると、AIはそれに引っ張られて遠回りします。日本語で「こうなってほしい」と書けば十分です。
03
「できました」を鵜呑みにする 必ず自分でも一度触ってください。AIが確かめたのは自分が想定した動きだけで、あなたの使い方ではありません。
04
会話が長くなっても同じ場所で続ける 話題が変わったら新しい会話を始めます。長い会話は、前半の情報が薄れて精度が落ちます。
05
うまくいった形を残さない 効いたプロンプトはメモしておくと、次から同じ品質が出せます。この記録も、そのメモ代わりです。

この記録に載せたやり取りは、実際の会話の抜粋です。アプリのコードは全体で約1,300行、すべてAIが書いています。
